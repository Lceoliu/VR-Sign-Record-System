# Assign exactly one of three assistance conditions per Interaction Run

Each Interaction Run receives exactly one immutable `AssistanceCondition`: `TextAndPointing`, `TextOnly`, or `SignOnly`; `PointingOnly` is not a valid state. The condition applies to all six phases and is assigned from a session-local shuffled block containing each condition once, with the slot consumed when Start creates the Run Plan even if that Run later aborts, and with the block reset whenever the Interaction application launches. Text and pointing visibility are derived from the enum rather than stored as independent booleans, preventing the unsupported pointing-without-text combination and making the experimental comparison explicit, at the accepted cost that restarting the application resets condition balancing.
